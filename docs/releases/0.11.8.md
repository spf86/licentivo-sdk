# Licentivo SDK 0.11.8

Release date: 2026-11-01.

- Renew the original metered reservation while a business callback runs, across
  Go, JavaScript, Python, Java, C#, C and the C++/Rust/Ruby native bindings.
  Renewals keep the operation ID, reservation ID and quantity unchanged; the
  server's default reservation TTL remains 900 seconds.
- Preserve pending commit/cancel records and unknown business outcomes after
  network failures or process interruption. Replaying a completed task does not
  execute its callback again.
- Protect Python task journals with operating-system file locks. A forked child
  must create a new Client instead of using the inherited parent Client.
- Keep Launch metered task identity stable across refreshed identity assertions
  and device credentials. Support Launch account authorization with floating
  licenses while retaining independent instance/logout behavior.

Upgrade the Licentivo server with these SDKs. Launch applications should use
Launch SDK 0.1.8 (which embeds this SDK) with Launch server 0.3.6-beta.
Preserve the existing cache, device credential and durable business results
when recovering unfinished tasks; explicitly resolve an unknown outcome only
after checking the actual result. Expired reservations cannot be revived, and
renewals do not cross the original UTC billing-period or authorization limit.
JavaScript callbacks must keep the event loop responsive; move long CPU work
to a worker.

Validation includes the shared 57 signature vectors, Python fork/locking
regressions, official and Launch metered-task recovery checks, and eight
920-second business callbacks against the unchanged 900-second server TTL.
The recorded long tests each executed the business once and consumed exactly
three units. These results do not certify every operating-system/toolchain
combination or external payment provider.

Supported languages: Go, Java, C, C++, C#, Python, JavaScript, Rust and Ruby.
Packages remain MIT-licensed.
